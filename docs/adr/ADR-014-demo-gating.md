# ADR-014 Demo controls gating
**Status: Proposed.** Demo panel (reset/replay/fault/clock) renders and its APIs respond only when `DEMO_MODE=1` and `APP_DATA_CLASS=SYNTHETIC` and the caller holds one of the roles the access table names for the endpoint. Reset truncates ops tables and re-seeds in one transaction; never touches identity keys config. Tokos inferred demo mode from missing keys — avoided.

**Role, amended 2026-10-17 (DECISION-LEDGER row 88, founder's final ruling at 14:44 ET).** This ADR said DIRECTOR. The demo reset is now the **director's and the coordinator's** — the header's "Start demo day" puts the day's data back and then starts the scenario clock, and a coordinator runs the demo day. The front desk is not included: their surface is the ramp iPad (PRD §1.1), and they are offered no control at all rather than a disabled one. The roles live in exactly one place, the `/api/demo/reset` row in `src/auth/access.ts`; `RESET_ROLES` in `src/modules/demo/reset.ts` and the header control both read that row (`rolesWhoCanCall`), so neither can drift from it. Everything else about the gate is unchanged, including the site check at the site being reset (`requireSiteAccess`) and the uniform not-found for any other site's id.
