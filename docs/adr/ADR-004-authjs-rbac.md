# ADR-004 Auth.js v5 + RBAC + site scoping
**Status: Auth.js Decided by founder; RBAC design Proposed.** `next-auth@beta` (5.0.0-beta.32), Credentials provider with seeded synthetic users (one shared demo password in config, printed on /login — DECISION-LEDGER row 59, superseding the per-role env secrets of row 57; every other secret stays in env, never in code or UI), JWT session carrying `userId` only; role and site re-read from `site_membership` per request. Roles: DIRECTOR, COORDINATOR, FRONT_DESK; dispatchers use a signed single-date link (`dispatcher_link`), not an account. Every handler goes through `requireSiteRole(siteId, roles)` and loads rows `WHERE site_id = session site`. Next 16 `proxy.ts` only redirects; it is not the authorization layer. ID-swap matrix in BUILD-PLAN.md §4. Alternatives: Clerk/WorkOS (vendor, later Entra via IdentityGateway). Evidence: https://authjs.dev/getting-started/installation ; npm next-auth@beta.
