# ADR-001 Durable timers and workers on Vercel + Neon
**Status: Proposed** (Firia, 2026-10-14). Needs Rudy's spike + TEST-INF-01 pass before Accepted.
**Context.** PRD NFR-03: timers survive restarts and fire within 5 s of due. Cron on Pro is 1-minute granularity, so cron alone cannot meet 5 s.
**Decision.** `ops.job` row is the source of truth (written in the same transaction as the domain change). On insert, publish a Vercel Queues message with `delaySeconds = due - now`, idempotency key = job id, and the row's `(dueAt, version)` as a **fence**. Consumer does a guarded claim in **one transaction** (`claimForWake`): `SELECT … FOR UPDATE`, refuse with a named reason if the job is cancelled, already DONE, DEAD, already CLAIMED, fenced out as superseded, or more than 1 s early, else `UPDATE ops.job SET state='CLAIMED', claimed_at=now(), claimed_by=$token, claimed_until=now()+2s`; every refusal is a no-op + **ack**, never a throw, because on an at-least-once unordered queue with no delay SLA all of them are expected traffic. The row lock spans the check and the claim, so two concurrent duplicate deliveries resolve to exactly one winner. The fence is `(due_at, version)` and deliberately **not** `version` equality: `reschedule` moves `due_at` and bumps `version` together (so a differing `dueAt` means the wrong generation and is dropped), while `reclaimIfExpired`/`markFailed` bump `version` and leave `due_at` alone (so a version merely *behind* the row is a legitimate retry of the same firing and must pass — an equality fence would disable Option A). **Option A, retuned (DECISION-LEDGER row 56 "Accepted by default (Firia, within founder locks)", Firia → Rudy relay 2026-10-14 14:22 ET, superseding the 3 s lease proposed for row 38 — PR #10, closed, so row 38 is not in this tree and row 56 only cites it):** the lease is **2 s**; at claim time the consumer publishes a re-wake delayed 2 s; a re-wake or redelivery that finds an expired lease (`claimed_until <= now`) reclaims it and fires through the same claim; one that finds the lease **still live re-publishes itself** for the rest of the lease + 250 ms, so a delivery that lands early — queue jitter, or clock skew between the claiming and the waking instance — no longer no-ops and drops recovery onto the 1-minute sweep (Veri review of PR #10, blocker 1); **every published `delaySeconds` is now a fractional number with millisecond precision** (`Math.ceil(ms)/1000`, no rounding up to whole seconds), which is what removes the per-hop penalty; a handler that outlives the lease **renews** `claimed_until` every LEASE/2 = 1 s on its own connection, fenced by the claim token, and abandons its commit if the renewal shows the claim gone; `claimed_by` carries a per-claim token that fences the DONE update; a failed handler throws and Queues redelivers with **bounded exponential backoff** (2 s, 4 s, … capped at 60 s) instead of at once. Simulated kill-after-claim lateness (jobs.test.ts, B-03 PR, jitter ≤1 s per delivery and early arrival ≤1 s): 2.0 s with no queue jitter; 4.0 s at 1 s jitter per delivery when the re-wake lands at or after expiry; **4.25 s worst case when it lands early**, because with exact delays that path pays only the 250 ms margin extra, for any amount of earliness. So p100 is **4.25 s, 0.75 s inside the 5 s bar** (was 6.2 s, 1.2 s over it, with the 3 s lease and whole-second delays). This holds only if Vercel Queues honours sub-second `delaySeconds`: that is **required and Unverified (TEST-INF-01)**, probed live by `GET /api/probe/delay` → topic `ppec-delay-probe` (consumer logs `[delay-probe] id=… requested=… actual=… ms`, no DB, works on previews). If Queues floors or rounds the delay, revert to the row 38 parameters (3 s lease, whole-second re-wakes) and report. Every-minute cron sweeper: fires overdue SCHEDULED jobs, reclaims CLAIMED past `claimed_until`, re-publishes jobs due in the next 7 days with no live message, and marks `DEAD` after 5 attempts (creating a RED task). Each deployment's first sweep writes `runtime_marker.active_deployment_id` and re-arms because queue messages are pinned to the publishing deployment. Queue-side tuning uses the only three knobs @vercel/queue 0.8.0 exposes: `retryAfterSeconds: 2` on the trigger (the lease, not the 60 s default), `visibilityTimeoutSeconds: 30` — the package's documented **floor**, so it cannot match the 2 s lease, which is precisely why Option A recovers through our own re-wake rather than through queue redelivery — and a `retry` callback that backs off 2 s → 60 s then acknowledges at 8 deliveries, standing in for the **`maxDeliveries` option and DLQ the package does not have**. All behind `JobScheduler` (schedule/cancel/reschedule) so AWS swaps to pg-boss on Fargate.
**Alternatives.** Cron only (fails 5 s). pg-boss in Vercel functions (needs a long-lived worker; no host for it in P1). Inngest / QStash (another vendor + BAA later; fine technically). Vercel Workflow `sleep` as the store (state lives outside our DB; harder AWS exit). 
**Consequences.** Queues is Beta: if it fails TEST-INF-01, fallback is the sweeper at 1-minute granularity plus a documented NFR-03 deviation (founder decision) or QStash behind the same seam. The measured kill-after-claim p100 above (4.25 s) holds 0.75 s of margin at 1 s delivery jitter, but it **assumes sub-second `delaySeconds` are honoured**, so **PPE-43 / NFR-03 stays UNVERIFIED until a live TEST-INF-01 run** on the synthetic prod deployment (row 18) both measures the real jitter and runs the delay probe (`GET /api/probe/delay`). Two outcomes: delays honoured ⇒ row 56 stands; delays floored or rounded to whole seconds ⇒ revert to row 38 (3 s lease, whole-second re-wakes), report the 6.2 s p100, and retune from there. The recovery parameters (lease, re-wake margin, delay precision) remain the knobs.
**Queues delivery contract (Athena, PR #21).** At-least-once, **unordered**, **no delay SLA** (`delaySeconds` is a "not before" floor), default redelivery 60 s, deployment-pinned, no DLQ. So the transport is an alarm clock only: correctness is the guarded claim plus the fence, and the 4.25 s p100 is a *tuning* claim that the live run has to confirm. `scripts/test-inf-01/delay-accuracy.ts` (**PROPOSED, not run** — needs a preview deployment and Firia's go-ahead) measures the distribution over 300 probes.
**Evidence.** https://vercel.com/docs/queues , /queues/concepts , /queues/pricing (Beta, at-least-once, delay ≤7 d, deployment pinning, no DLQ); https://vercel.com/docs/cron-jobs/usage-and-pricing (Pro per-minute); npm pg-boss 12.38.0; PGlite claim test research/pglite-apply.log.
**Schema note (B-02, PPE-10, 2026-10-14).** `ops.job` has `claimed_until` (lease, read by the sweeper) plus `claimed_at`/`claimed_by` (audit only). ARCHITECTURE.md §6 and schema-draft.ts were aligned to this; the earlier "CLAIMED older than 2 min" rule is replaced by `claimed_until < now()`.
