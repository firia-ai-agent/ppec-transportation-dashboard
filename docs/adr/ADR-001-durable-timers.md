# ADR-001 Durable timers and workers on Vercel + Neon
**Status: Proposed** (Firia, 2026-10-14). Needs Rudy's spike + TEST-INF-01 pass before Accepted.
**Context.** PRD NFR-03: timers survive restarts and fire within 5 s of due. Cron on Pro is 1-minute granularity, so cron alone cannot meet 5 s.
**Decision.** `ops.job` row is the source of truth (written in the same transaction as the domain change). On insert, publish a Vercel Queues message with `delaySeconds = due - now` and idempotency key = job id. Consumer does a guarded claim `UPDATE ops.job SET state='CLAIMED', claimed_at=now(), claimed_by=$deployment, claimed_until=now()+3s WHERE id=$1 AND state='SCHEDULED' AND due_at<=now()+1s RETURNING *`; 0 rows ⇒ ack and stop. **Option A (DECISION-LEDGER row 38 "Accepted by default (Firia, within founder locks)", Firia → Rudy relay 2026-10-14):** the lease is 3 s; at claim time the consumer publishes a re-wake delayed 3 s; a re-wake or redelivery that finds an expired lease (`claimed_until <= now`) reclaims it and fires through the same claim; one that finds the lease **still live re-publishes itself** for the rest of the lease + 250 ms (whole seconds, because `delaySeconds` precision is Unverified), so a delivery that lands early — queue jitter, or clock skew between the claiming and the waking instance — no longer no-ops and drops recovery onto the 1-minute sweep (Veri review of PR #10, blocker 1); a handler that outlives the lease **renews** `claimed_until` every 1.5 s on its own connection, fenced by the claim token, and abandons its commit if the renewal shows the claim gone; `claimed_by` carries a per-claim token that fences the DONE update; a failed handler throws and Queues redelivers with **bounded exponential backoff** (2 s, 4 s, … capped at 60 s) instead of at once. Simulated kill-after-claim lateness (jobs.test.ts, B-03 PR): 3.0 s with no queue jitter; 5.0 s at 1 s jitter per delivery when the re-wake lands at or after expiry; up to **6.2 s when it lands early**, because that path pays one more hop (≤1 s of whole-second delay granularity + ≤1 s of jitter). So p100 is **1.2 s over the 5 s bar on the early path at 1 s jitter per delivery**, and 4.7 s (inside the bar) at 0.25 s jitter; the re-wake-at-expiry path has exactly zero margin at 1 s jitter. Closing that gap is a ledger decision, not a code one: a ~2 s lease (Veri's suggestion) and/or sub-second `delaySeconds` if TEST-INF-01 verifies the precision (2 s lease + exact delays ⇒ 4.25 s, 0.75 s margin). Every-minute cron sweeper: fires overdue SCHEDULED jobs, reclaims CLAIMED past `claimed_until`, re-publishes jobs due in the next 7 days with no live message, and marks `DEAD` after 5 attempts (creating a RED task). Each deployment's first sweep writes `runtime_marker.active_deployment_id` and re-arms because queue messages are pinned to the publishing deployment. All behind `JobScheduler` (schedule/cancel/reschedule) so AWS swaps to pg-boss on Fargate.
**Alternatives.** Cron only (fails 5 s). pg-boss in Vercel functions (needs a long-lived worker; no host for it in P1). Inngest / QStash (another vendor + BAA later; fine technically). Vercel Workflow `sleep` as the store (state lives outside our DB; harder AWS exit). 
**Consequences.** Queues is Beta: if it fails TEST-INF-01, fallback is the sweeper at 1-minute granularity plus a documented NFR-03 deviation (founder decision) or QStash behind the same seam. The measured kill-after-claim p100 above leaves no margin at 1 s delivery jitter, so **PPE-43 / NFR-03 stays UNVERIFIED until a live TEST-INF-01 run** on the synthetic prod deployment (row 18) measures the real jitter; the recovery parameters (lease, re-wake margin, delay precision) are the knobs to retune once it is measured.
**Evidence.** https://vercel.com/docs/queues , /queues/concepts , /queues/pricing (Beta, at-least-once, delay ≤7 d, deployment pinning, no DLQ); https://vercel.com/docs/cron-jobs/usage-and-pricing (Pro per-minute); npm pg-boss 12.38.0; PGlite claim test research/pglite-apply.log.
**Schema note (B-02, PPE-10, 2026-10-14).** `ops.job` has `claimed_until` (lease, read by the sweeper) plus `claimed_at`/`claimed_by` (audit only). ARCHITECTURE.md §6 and schema-draft.ts were aligned to this; the earlier "CLAIMED older than 2 min" rule is replaced by `claimed_until < now()`.
